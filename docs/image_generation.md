# 主对话生图

在“设置 → AI 接口 → 生图接口配置”中启用生图，填写独立的接口地址、API Key 和模型。生图配置与角色聊天、TTS 配置分开保存，Windows 和 Android 共用同一套功能。

## 使用

1. 协议格式优先选择“自动识别”。填写服务商提供的完整生图地址，或选择对应协议并填写基础地址。界面会显示当前识别结果。
2. 设置模型、宽高、比例与输出格式后保存。服务商或模型不支持的尺寸、格式仍可能被服务端拒绝。
3. 在主对话中发送明确请求，例如“帮我画一张夕阳下的库肯岛，水彩风格”或“生图：坐在窗边的莱莎”。没有指定主要人物时，默认主角为莱莎；明确指定其他人物、群像或无人画面时遵循你的要求。只发送“生图”“生成一张图片”等无主题命令时，会结合当前存档最近的有效对话、旁白、世界背景、位置和时间组织画面；莱莎对话还会沿用当前莱莎的人物及外观设定，其他角色的衣着不会套用给她。普通聊天仍正常进行。
4. 打开虚拟手机，点击底部最右侧的生图管理图标。外围转圈表示有任务正在生成，红点表示有尚未查看的完成结果；该入口替代原设置快捷方式，进入后在手机内查看图片，返回到手机图标页。
5. 图片会加入当前历史消息；原图同时保存在生图管理中，可放大查看。任务失败可查看原因并手动重试。

生图完成时若角色回复仍在进行，会先等待本轮回复结束再插入图片消息，避免破坏流式输出。切换角色或清空/切换对话数据后，先前任务仍保留在生图管理中，不插入新的聊天。

无主题生图使用发送时的存档场景快照，默认主角固定为莱莎；最近最多 12 条有效对话，历史内容限制约 4200 字符。角色与世界详细设定遵循设置中的注入开关。译文、内部控制标签、旧生图通知和失败信息不会用作新画面主题，也不会额外调用一次聊天模型来改写提示词。

## 支持的协议

| 格式 | 提交与结果 | 配置说明 |
| --- | --- | --- |
| OpenAI Images | `POST /images/generations`，解析图片 URL 或 Base64 | 支持 OpenAI 兼容转发服务；模型填写图像模型 |
| OpenAI Responses | `POST /responses`，使用 `image_generation` 工具 | 模型填写支持图片生成工具的 Responses 模型 |
| Gemini | `generateContent`，解析 `inlineData` 图片 | 模型填写对应图像模型，Key 使用 `x-goog-api-key` |
| 通用同步 JSON | 一次提交，读取图片 URL / Base64 | 需要填写实际生图端点；请求采用 `prompt/model/width/height/size/aspect_ratio/output_format` |
| 通用异步任务 | 一次提交，依据状态地址或任务 ID 轮询 | 可设置状态地址模板，例如 `/v1/tasks/{task_id}` |
| ComfyUI | `/prompt → /history → /view` | 使用基础文生图工作流；模型填服务器已安装的 checkpoint 文件名 |

自动识别依据已知主机和明确端点；未知地址使用通用 JSON 请求，并从首次响应判断同步图片或异步任务。它不会轮番调用不同的生成接口猜测协议。服务商若采用专用签名、multipart 表单或不同请求字段，需要进一步添加对应适配，不能仅靠响应解析转换请求格式。

Starlight 可填写 `https://starlight.uno/v1`，协议选择“自动识别”或“OpenAI Images API”，实际提交地址为 `https://starlight.uno/v1/images/generations`。填写根地址 `https://starlight.uno` 也会补全到该端点；模型仍需填写服务商支持的图像模型。只有已识别的服务才会补全 API 基础地址，未知服务的 `/v1` 不会一律当作 OpenAI。若服务商文档要求其他完整端点，直接填写该端点或在高级配置中指定提交端点，并选择对应协议。设置页会显示实际提交地址。

成功响应支持标准 JSON、带 UTF-8 BOM 的 JSON、直接返回的图片二进制，以及含完整图片结果的 SSE 响应。流式进度或局部图片片段不会当作完成图片。若接口返回的是网页 HTML（即使 HTTP 状态为 200），会提示检查生图端点，不会把网页保存成图片，也不会为寻找正确地址再次提交付费请求。

对于反向代理或自建服务，可手动指定协议、提交端点和状态端点。通用协议与 ComfyUI 的 Key 可留空；填写后会用于鉴权。公网地址使用 HTTPS，本机开发地址可使用 localhost/loopback HTTP。

## 数据与失败处理

- 原图及任务记录存放在应用支持目录的 `image_generations/` 下，重启后仍可查看；聊天历史另存缩略图。
- API Key 存在系统安全存储中，不写入生图配置。不要把 Key 写在 URL 中。
- 生图接口配置参与设置备份；Key 仅在用户选择导出服务密钥的备份中携带。新密钥备份为 v2，兼容旧 v1。
- 普通聊天备份保存图片消息及缩略图，当前不打包生图管理中的全部原图。迁移设备前应另行保存需要保留的原图。
- 接口超时不等于远端未生成。结果未知时不会自动重新提交；手动重新生成前会提示可能重复计费。
- 当前接入验证使用本地与 Mock 服务，未执行真实付费生图请求。
