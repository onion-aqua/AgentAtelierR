# 角色资源的私有持久缓存

首次打开某套内置服装时，验证并解密 `.aarpack`，将原始解密文件保存到
`getApplicationSupportDirectory()/protected_character_cache_v1`。
Android 对应应用私有 data/files 目录，普通文件管理器不能访问。
后续冷启动、切回服装以及覆盖安装后，可以复用未变化的资源。

- APK 仍只包含加密角色资源。加密构建工具同时生成小型 `index.json`，
  记录加密对象的 SHA256 和大小；缓存命中无需重新读取 APK 内的大包。
- 缓存身份包含包身份、加密内容 SHA256、密钥指纹和缓存格式。
  修改资源、轮换密钥、资源热更新与回滚均会选择相应的新身份。
  代码更新而资源未变时可继续复用。
- 缓存校验失败或不完整时重新解密原包；缓存无法写入时仍正常加载。
  大块校验、解包和解密在后台 isolate 执行。密钥不写入缓存。
- 仅按需缓存服装和预览，设置容量上限并清理旧数据。
  缓存的是原始资源，自定义贴图仍在其上覆盖，导入服装继续使用原有存储。
- Android 云备份和设备迁移明确排除此目录。应用 JSON 数据导出不包含它。
  清除应用数据或卸载会移除缓存，下次需要重新生成。

热更新仍先检查真实资源对象的完整 SHA256、快照兼容性及回滚条件。
已通过内容健康检查的包保存与密钥和验证版本绑定的小记录，
避免每次冷启动将所有未使用服装再次解密；首次内容检查仍执行 AES 和 JSON 检查。

缓存省掉重复 AES、解包和 APK 大包读取，PNG 解码、GPU 纹理与 Spine
骨架初始化仍须执行。日志中的 `Startup` 和 `CharacterAssets` 分别记录
资源检查、缓存命中与 Spine 图集/骨架耗时，用于区分剩余加载成本。

## 本次验证（2026-10-23）

76 项缓存、加载、热更新和资源行为回归通过，全项目静态分析通过。
使用临时素材连续执行两次打包工具，核对生成索引的对象大小、SHA256
及重复构建的身份稳定性；已覆盖 Windows 路径分隔符导致索引被清理的问题。

本机 Flutter 测试读取实际 13,010,373 字节角色包：首次解密并持久化
约 1,229 ms，新建加载器从磁盘缓存读取约 116 ms，两次加载合计只读取
一次原加密包。此数据是 Windows 本机测试，不代表 Android 整体启动时间。
