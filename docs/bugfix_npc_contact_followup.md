# 场景 NPC 交换联系方式漏识别修复

## 设备证据

2026-10-11 读取 `a43d2d7a` 的现有聊天及应用运行日志。手机仍为 `1.0.4`、versionCode 38；本次没有覆盖安装、清空数据或发送在线聊天。

实际对话中的用户请求为“我请求塞莉和我交换微信”。模型使用正确的 `角色[serri]` 身份回复：

> WeChatね。ええ、交換しましょう。ただ、植物の観察中は気づかないことがあるから、返事が遅くても許してね。

下一轮用户说“或者SMS也行”，模型回复：

> SMSでも構わないわ。そちらのほうが都合がいいなら、交換しましょう。

旧规则漏识别了这两种日语同意；第二轮输入也因为没有再次写出“加／交换”而没有生成联系请求。运行日志里卡菈的“よいぞ、交換してやろう”属于同类漏识别。本次证据表明 NPC 身份已经正确输出，无需把该问题归因于模型没有召唤出人物。

## 修改

- 支持明确的日语交换邀请、带明确渠道的许可表达，保留拒绝和犹豫优先检查。日语转述、否认、旁白、译文及隐藏模型内容不能代替本人同意。
- 明确的换渠道短句可以承接紧邻上一轮已完整生成的联系请求，沿用原目标；不能通过其他人物称呼偷偷更换目标。
- 跟进上下文只在当前界面内短暂保留，绑定完整回复 ID、当前角色和存档修订。取消、失败、撤回、不相关的下一轮、自动续写、换档或换角色都会使其失效。重启不从旧历史恢复邀请。
- NPC 本轮同意后仍显示用户确认，只有点击“加入信息”才建立联系人。确认窗口的接受、拒绝或关闭都会消费邀请，避免反复弹出。

如果旧包已经漏掉确认，更新后请在当前对话里重新明确提出一次交换联系方式。修复不会扫描历史并自动添加联系人。
