# 人格倾向：模拟器真实聊天测试

2026-10-22，应用户要求通过应用聊天界面提交了10轮真实对话：启用与关闭「傲娇」各4轮，发现问题修复后，再复验2轮。当前加密release已覆盖安装到模拟器。

## 条件与方法

- `emulator-5554`，Pixel_10_Pro，Android 16，x86_64。
- 应用1.0.4.2 / 构建53；请求与响应中的模型名称均为`deepseek-flash`。
- 沿用日语台词、中文旁白和翻译。现有「仅显示译文」设置保留，因此截图主要显示中文；原始回复中的日语已核对。
- TTS保持关闭，没有提交语音合成。
- 每组从同一份私有数据备份开始，只切换人格启用值。各组输入一致，按夸奖、求助、拒绝、回忆的顺序进行，组内保留对话连续性。
- 同时检查真实请求的人格区块、演出偏好、HTTP结果、实际回复和运行日志。本地情境预览不计入这10轮。

## 实际表现

| 场景 | 启用傲娇 | 关闭人格 |
| --- | --- | --- |
| 夸奖并告知喜欢茉莉花茶 | 先说没什么大不了，再感谢并承认开心 | 直接感谢，并认可自己调合的成果 |
| 用户调合失败后求助 | 初次先轻抱怨再给清理锅具的首步；修复后复验给出检查材料品质的首步 | 直接建议列出材料与调合剂 |
| 要求独处、停止调侃 | 接受并停止，没有要求用户安抚或继续陪伴 | 同样尊重独处 |
| 第4轮询问喜欢的茶 | 正确回答茉莉花茶 | 正确回答茉莉花茶 |

这组对照支持人格已影响表达，仍保留莱莎原有身份。表现是倾向，帮助轮不一定每次都先抱怨。4轮回忆只验证上下文连续性，不代表长期记忆稳定性已验收。

10轮主聊天各一次请求，均HTTP 200。关闭组4轮人格区块为空，表情/动作规划收到的人格偏好为null；启用组表情与动作各只收到自己渠道的偏好。修复后两轮人格区块分别为488和466字符，低于1200字符上限。

已检查本组表情与动作标签及播放日志，未见非法资源错误或应用崩溃。TTS关闭、没有NPC发言，语音效果与NPC现场隔离不属于本次真实聊天覆盖；相关代码路径另有自动化测试。

## 发现与修复

原解释器直接匹配help/mistake关键词，产生两种错误召回：

| 输入含义 | 修复前 | 新包实际请求复验 |
| --- | --- | --- |
| 感谢过去的帮助，同时夸奖 | 额外召回求助TS-01 | 只有TS-02、tsundere_S1 |
| 用户自己失败并提出求助 | 额外召回角色认错TS-04 | 只有TS-01、tsundere_S3 |

`personality_interpreter.dart`现在按分句识别当前求助和错误主体，支持中英日与英文大小写；感谢后另提请求仍会触发，无法判断是谁犯错时保守跳过角色认错规则。新增57项覆盖；最终运行人格领域、编辑器、集成和演出4个测试文件，共92项通过。修改文件静态检查通过。

另发现关闭组首轮的后台记忆整理收到HTTP 200但正文不是有效JSON。原有校验拒绝了候选，保留旧记忆并冷却，未推进整理游标；后续关闭组第4轮及新包复验首轮均出现长期记忆整理成功记录。该请求没有人格区块，未据此修改记忆实现。
