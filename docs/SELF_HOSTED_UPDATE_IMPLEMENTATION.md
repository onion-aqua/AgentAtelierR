# 自托管更新：已实现内容与接入

实施日期：2026-10-19。显示版本保持 `1.0.4.1`；正式 `stable` 渠道已发布序号 54，对应受保护安卓 build 51。旧客户端需完整安装一次正式包以启用正式更新渠道。前期隔离渠道真机范围见 [测试记录](update/DEVICE_TEST_2026-10-19.md) 和 [壁纸记录](update/WALLPAPER_DEVICE_TEST_2026-10-19.md)；本次更新内容和用法见 [发布说明](update/RELEASE_1.0.4.1_BUILD50.md)。

## 用户操作

- 应用首屏加载完成后异步检查更新；恢复前台按频率检查，不阻塞聊天。
- 新版本提示可用右上角 `×` 或系统返回关闭，同一发布默认静默 24 小时。
- PC Agent 限时问题优先；更新提示等待前台主页面，不覆盖扫码等其他路由。
- 设置 → 关于 → 版本与更新，可手动检查、切换来源、设置自动检查、清缓存及继续安装。虚拟手机里的设置使用同一更新状态。
- “立即更新”准备目标版本；“完整安装包”保留全量下载；“GitHub 自行更新”打开对应 Release。
- 只有资源变化时，无需安装 APK。资源先下载、校验并暂存，在下次启动、读取角色和提示词之前原子激活。
- 含程序代码变化时，下载完整 APK，检查文件摘要、包名、版本、签名及安装权限，再打开 Android 系统确认。取消安装后可继续。

## 跨版本与安全

客户端读取签名清单，按 `release_seq`、`release_id` 和完整签名负载摘要记录发布身份。显示版本名不作为补丁基线。同一序号不能换成另一份发布，旧镜像不能降低已经信任的序号。

各已配置镜像并行查询，选取签名有效且属于当前平台/渠道的最高发布序号；同序号默认优先 Gitee，也可选择 GitHub 优先。这样 Gitee 尚未同步时，仍可发现备用来源的新版。安装目标来自签名清单，Release 正文只用于显示。

资源清单描述完整目标快照，客户端只获取本地缺少的内容对象。跳过中间版本也会取得全部变化；新快照不再继承已被删除的旧覆盖项，应用内资源仍是最低回退。资源目录与用户存档、记忆、凭据、壁纸和模型目录分离，清缓存不清理用户数据。

资源受运行时、资源 API 和预置信任的密钥标识约束，校验失败保留旧快照。启动健康检查包含对象 hash、JSON 可读性和加密角色包解密，错误快照可回退。新的 APK 内置资源基线会取代更旧的资源覆盖。

APK 支持 HTTPS 镜像、Range 续传、下载取消与完整性验证。HTTPS 跳转逐次校验，不允许降级为公网 HTTP。Android 安装桥只接受应用管理目录中的包，并在安装前重新验证。

## 本地配置

从 [更新构建配置示例](update/update-build-config.example.json) 复制到忽略目录 `.asset_protection/update_server.json`，填写实际受信任 HTTPS 清单入口、Ed25519 公钥、发布序号和兼容标识。签名私钥保存在仓库外，不能放入 APK。

保护构建脚本会加密注入本地更新配置。缺少配置时，联网检查和旧资源覆盖均禁用。示例中的地址和公钥是占位值；单独填入服务器 IP 不会生成更新服务。

加密配置降低明文误泄露，但 APK 中可解密的配置不能当作服务器秘密；更新真实性依靠离线 Ed25519 私钥和内置公钥验证。

## 发布工具

完整步骤见 [发布工具说明](update/README.md) 和 [清单协议](update/MANIFEST_V1.md)：

1. `Sync-ReleaseNotes.ps1` 按预期 tag 读取 Gitee/GitHub Release 正文，生成可缓存的 `notes.md`。
2. `New-ResourceSnapshot.ps1` 从明确指定的受管理资源树生成完整 canonical 快照与按 SHA-256 去重的对象。
3. `New-UpdateManifest.ps1` 签名发布清单，支持 APK、资源或两者组合。序号和发布身份不可复用。
4. `Test-UpdateManifest.ps1` 核验签名、schema 和本地制品。
5. 所有不可变对象上传并验证可访问后，才原子切换渠道清单。

角色/服装明文资源继续遵循本项目不上传仓库的规则。远程资源目录应使用保护脚本输出的加密包。保护脚本现在会校验并复用未变化的密文；内容、密钥或格式变化时重新生成随机 nonce，不使用固定 nonce。

发布工具生成本地产物；服务器基础设施已独立部署，正式渠道已切换到签名序号 54。部署与发布步骤见 [服务器说明](update/SERVER_DEPLOYMENT.md)。

## 当前边界

- 旧客户端必须先完整安装一次带更新器的引导版本，才能收到后续应用内更新提示。
- 当前 Android 未集成二进制 patch 引擎，平台明确上报不支持差分；代码更新走完整 APK。协议、精确基线选择和发布字段已预留，但不能宣称已完成 APK 增量重建。
- Windows 更新 helper 尚未实现；Windows 继续使用完整 ZIP 更新。
- 已构建受保护 release 测试 APK，真机由 build 46 覆盖安装至 build 47，再经应用下载和 Android 安装器升级到 build 48；已安装 APK 与签名目标摘要一致，现有可见存档保留。
- 已通过 SSH 部署独立 HTTPS 静态更新路径，正式 build 51 已加密注入 stable 渠道配置。Ed25519 签名私钥没有上传，配置位于 Git 忽略目录；本地正式构建必须显式提供对应的 `-UpdateConfig`。
- 正式签名渠道序号 54 和 Gitee 默认 main 分支的相对更新指针已发布。Gitee Release API 认证仍不可用，Git raw 渠道可正常读取；不能把 Git 指针更新描述为已修改 Gitee Release 页面。
- 进程退出后会重新取得并验签清单，再复用已下载的 APK/断点文件；未实现离线恢复安装计划。
