# 背包与状态恢复

## 普通物品入包

开启 Agent 后，可以在对话中说“把一个苹果放入背包”或“把两本书放入背包，标签为纪念品”。模型通过 `add_inventory_item` 写入真实背包，不需要先进入地图采集场景。

- 名称、数量和已指定标签以用户要求为准；分类及未指定的描述标签由模型根据物品语义生成。
- 描述标签会显示在背包中，随消耗、存档、读档、备份和重启保留，不会直接赋予人物数值效果。
- 同一轮同名物品的重复工具调用不会重复入包；新一轮明确要求可以再次添加。
- 只有明确标注为食物的物品才能用于进食。苹果模型、防水用品等不能因名称含有食物或水字就自动变成可食用物品。
- Agent 关闭时，对话不能写入背包。是否执行入包仍依赖所用模型正确调用工具；仅文字回复“已放入”不代表操作成功。

## 存档与状态

新档初始化为心情 0、精力 100、亲近感 0、好奇心 20，状态标签同步显示对应档位。每个存档保存自己的状态、情绪、结算记录和剧情时钟。

旧存档没有人物状态字段时恢复新档默认值，不再继承上一个存档。清除聊天并选择“一并删除”长期记忆时，当前人物状态、关系点数和剧情时钟一并初始化；选择保留记忆则保留状态。清除操作不改写已有存档槽位。存档仍需按原有方式保存进度。

新档、读档和清除对话都会使旧请求失效，迟到的表演规划不能再写入当前状态。

## 休息与时间跳转

表情规划器同时参考本轮用户输入和回复，判断主角是否实际经历了休息或时间跳转，纯旁白也可结算。

- 已睡了一觉：精力至少恢复到 80。
- 剧情跳过至少一天：精力至少恢复到 70；明确的多天跳转支持最多 30 天。
- 普通休息至少 15 分钟：精力增加 10，最多 100。
- 剧情时钟关闭时仍可恢复精力，但不推进时钟或扣饱食度。
- 时钟开启时先结算饥饿消耗，再应用睡眠或跨日恢复下限，避免恢复被整段跳时的扣除完全抵消。饱食度不会自动补满。

“打算去睡”“昨晚没有睡”“如果过几天”等未实际发生的情形，以及仅用户本人睡觉，不应触发主角恢复。跨日仍持续劳累时不按日常恢复处理。这些语义区别由模型识别，本地负责数值范围、同轮去重和存档隔离。测试覆盖模拟工具调用与结算流程，未使用在线模型或手机做端到端实测。
