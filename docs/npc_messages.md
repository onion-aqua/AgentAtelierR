# NPC 信息与存档

## 使用

主界面打开虚拟手机，点击底部的“信息”图标。联系人列表只显示已经在主对话中确认添加的 NPC，避免一次性展示整个角色目录。主聊天识别“添加好友、交换联系方式、微信、QQ、短信/SMS、LINE、Discord、Telegram、邮箱”等明确表达；只有目标 NPC 在本轮自己的台词中明确同意，应用才会显示确认卡片，用户点击“加入信息”后才建立联系人。多个同名或候选 NPC 会先让用户选择。普通提及人物不会触发添加。联系人列表可按中文、日文、英文名及别名搜索，已有会话按最近消息排列。点击联系人进入会话，输入文字并发送，NPC 的回复会逐步显示。莱莎使用现有资源目录中的 33 名 NPC；苏菲使用独立的 10 名联系人，两位普拉芙妲分开显示。

回复复用设置中的主 LLM 服务、当前配置槽、模型及思考参数，无需另填 API。未启用 AI、未配置 API Key 或网络请求失败时会显示提示，不生成模拟回复。

在紧接上一轮已完整回复的联系请求时，也可以说“或者 SMS 也行”“那换成 QQ 吧”，无需重复人物名和“交换”二字。仍须由同一目标 NPC 在新回复中亲自同意，再点击“加入信息”。日语“ええ、交換しましょう”“SMSでも構わないわ”等明确同意也支持识别。普通平台提及、旧历史、已取消或失败的请求不会触发；转到其他话题、撤回、换档、切换角色、重启应用或关闭添加确认后，需要重新明确提出联系请求。已经错过确认的历史对话不会自动补加。具体修复与验证见 [NPC 联系请求跟进修复](bugfix_npc_contact_followup.md)。

信息界面右上角的设置可选择 NPC 回复语言和翻译语言，默认分别跟随当前主角（莱莎或苏菲）的语言设置，主设置变化会自动生效；也可以单独选择中文、日文、英文，翻译还可选择“不翻译”。选择后立即保存，返回会回到打开设置前的联系人列表或会话，未发送草稿保留。设置按角色保存并包含在数据备份中，不改变主聊天的语言选择。

每次发送捕获本轮语言，更改设置只影响后续消息。回复出现明确的语言不符时，只纠正已经生成的正文一次，避免重新执行故事或工具；仍不符合时标记失败，可手动重试，不作为已确认记忆。短句、人名、中日文共用汉字词等无法可靠判断的内容保守放行，校验不是完整的语义语言识别。

选择翻译语言后，NPC 完成的回复会另行生成译文，并与原文一起保存。这不依赖主聊天的“独立翻译”开关；私信始终使用独立翻译。译文也检查语言，明显错误最多纠正或重试一次；失败不会丢失原文，也不会保存明显错语的译文。历史消息不会因新设置重新翻译。

每位联系人拥有独立的输入草稿和聊天记录。发送中可以停止，失败或中断后可点击“重试”，重试不会重复添加用户消息。离开会话或关闭虚拟手机后，已发出的请求会继续；切换角色、新建或读取存档、导入备份时会停止旧请求，迟到的回复和译文不会写入新存档。

返回操作先从会话回到联系人列表，再回到手机桌面。键盘打开时先关闭键盘。页面和气泡跟随液态玻璃设置实时更新。

## 记忆与存档

私信原文、译文、时间和完成状态完整保存在当前角色数据中，并自动更新当前使用的本地存档。也可通过原有存档和备份功能保存、读取、导入、导出。新存档从空私信开始；旧版本存档没有此字段时也从空记录开始。不同存档、不同角色的记录独立。

私信记忆基于已保存的完整记录，给 LLM 的上下文按长度限制提取近期消息和与当前问题相关的旧消息。原始历史保留完整对话回合，最多 24 条，并按普通 18000 字符、兼容模式 6000 字符裁剪；当前输入完整保留。检索片段预算另为 7500 / 2400 字符。这是上下文裁剪与旧记录检索，不是额外的 LLM 滚动摘要压缩。主聊天明确提到某个 NPC，或继续该 NPC 最近参与的话题时，会注入该 NPC 的记录及身份设定，让他能自然回忆先前的交流。直接找 NPC 并提到约定或关键词，有助于检索较早的对话。实际回复仍取决于所配置模型的上下文理解能力。

某位 NPC 的私信不会自动成为主角或其他 NPC 的记忆。没有收到完整回复的提问会标记为未完成；失败和中断的回复不会作为已确认事实。私信中的约定不代表已经见面、移动地图或执行任务，也不会直接修改背包、人物状态或控制 PC Agent。

记录使用 `npcChats` 字段，版本为 `1`，按稳定 NPC ID 分线程保存，并在同一字段的 `contacts` 数组中保存已确认的联系人 ID。旧存档如果已有非空聊天记录，会自动把这些线程视为已添加；空线程不会填充联系人。运行缓存使用独立角色命名空间 `npc_chats_v1.<characterId>`。API Key 继续通过既有 SecretStore 读取，不保存到私信记录中。导出文件包含聊天内容和联系人列表，请按普通聊天备份处理。

## 验证与构建

自动测试使用可替换的测试回复源，覆盖流式回复、正文过滤、并发联系人、重试、超时、停止、换档隔离、译文保存、记忆检索、备份恢复、手机内返回和窄屏布局。本轮增加默认语言跟随、覆盖设置持久化与旧备份兼容、设置内返回保留草稿、语言错误有界纠正、异步语言快照、译文语言校验和上下文预算测试。测试回复源不参与正式运行，自动测试通过不等同于真实在线模型验收。

本次已通过联系人检测、数据模型、服务、存档、提示词、页面和主聊天入口相关测试；新增覆盖了平台识别、普通提及不触发、同名 NPC 选择、明确同意/拒绝、否定/引用/假设请求排除、未添加联系人调用拦截和联系人存档往返。项目 Flutter 静态检查无问题。加密 Debug APK 已成功构建并覆盖安装到 `a43d2d7a`。尚未发送真实线上 NPC 请求，实际回复需要使用设备中配置的 LLM 验证。

Android 构建使用项目加密脚本：

```powershell
powershell -ExecutionPolicy Bypass -File .\tool\build_protected.ps1 -Target apk -Mode debug
```

产物：`build/app/outputs/flutter-apk/app-debug.apk`。Debug 模式用于测试，运行流畅度和稳定性不能代表 Release 包。
