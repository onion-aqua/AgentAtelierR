# 多规划器与组合动作接入

## 当前执行链

主模型输出 → 固定段落 ID → 表情、动作、语音并行规划 → 校验并合并 → 台词播放时进入动作队列 → 本地分阶段混合播放。

表情仍使用现有资源表情与强度映射；TTS 驱动口型。组合动作不写入脸部轨道。业务工具和记忆整理不属于动作执行器。

动作目录包含原有运行时动作和 132 个 Motion Lab 组合。组合只在实际动画齐全、基础姿势匹配且不是盘腿姿态时提供。盘腿仍通过 posture 通道切换；不是把站坐组合强加到盘腿模型。

本地检索以描述与输入文本的二元字符重合度排序，发送最多 16 个资源候选及原有语义动作。模型可以返回 request_catalog=true 扩大一次目录。检索不是语义嵌入，跨语言召回可能较弱，完整目录扩展是回退路径。无结果或规划失败保持现有状态。

## 资源适配

tool/import_motion_recipes.dart 从两个已交付清单生成 assets/data/motion_recipes.json；不包含候选清单、图片或骨骼二进制。

只取 motion_add/oneshot 身体动画。原文件的循环层改为单次有限播放；同轨道以及 B 与 F/G 冲突时顺序拆分，D 一次性反应独占一个阶段。进入和退出混合 0.34 秒，阶段长度由实际动画时长和速度决定，阶段切换不减小原动画权重。动作队列及资源版本校验沿用现有系统。

这些顺序是保守的本地适配，不代表已经人工编排或确认了每个组合的表演语义。validation=structural_only 表示已检查结构，尚未完成逐个视觉验收。

## 验证与边界

测试覆盖目录打包读取、132 个唯一 ID、轨道冲突、脸部隔离、姿态/资源过滤、检索、目录扩展、独立失败回退和旁白顺序。另已对照四套 scan.json 检查全部引用的动画名称存在。

当前仍等待三个规划结果后进入既有播放流程；迟到结果分段接入、自由分部位表情、逐段音频时间锚点尚未在本次接入中实现。不能把本地结构检查等同于真机流畅性验收。
