# 手机联动：中继设置、限期绑定和单向解绑

PC 插件和手机 App 各自配置中继。手机入口为「PC Agent 联动 → 云中继设置」。内置服务只显示「默认已配置」；填写自己的 HTTPS origin 后保存才会用于之后的扫码，留空恢复内置默认。没有内置配置的公开构建可以先填写地址，也可以通过扫码显式信任地址。HTTPS origin 不得包含账号、路径、查询或片段。二维码中的服务器地址必须与已选择的地址一致，发现不一致时应先修改设置并重新扫码。

修改默认中继不会把已有设备凭据发往新服务器。每份已保存的绑定保留自己的原始中继地址、独立随机设备 token、缓存和事件游标。它们继续向各自原始中继同步；如不再使用，应单独解绑。中继地址在默认页面隐藏并不等于对网络观察或二维码实现保密。

PC 新建二维码时选择 1、3 或 7 天的绑定有效期，手机不另行选择。新服务使用 `auto_confirm: true` 和 `binding_ttl_seconds` 创建配对；手机二维码内部 JSON 和 claim 请求保持 relay v1 不变，新生成二维码默认使用 [v2 加密封装](qr-envelope-v2.md)，旧明文 v1 仍兼容。扫码后手机可以直接得到 `confirmed` 状态，无需 PC 再确认。旧中继仍可返回 `pending_confirmation`，客户端保持兼容并显示等待 PC 确认。PC 仍自行选择共享工作区和历史权限。

`binding_expires_at` 是可选的 ISO 时间字段，可由 claim、配对 status 或设备快照返回。手机显示到期时间，在到期后禁用回答和任务发送，清除连接及内容缓存。服务端仍是最终授权依据，到期设备沿用 `DEVICE_REVOKED` / `device.revoked`；配对 status 的 `revoked` 也作为终态处理。缺少该字段的原有绑定保持原行为。

两端均可单向解绑，不要求对方在线或确认。手机解绑先通过 `FlutterSecureStorage` 原子移除本机绑定和缓存，同时保存最小待撤销记录：原始 origin、设备 ID、设备 token 和排队时间。前台立即恢复未绑定状态，可再次扫码；后台只对原始服务器重试 `DELETE /v1/devices/:id`，不执行其他操作。网络失败时页面明确显示服务器撤销尚在等待；此时云端原授权尚未撤销。恢复前台、定时同步或手动刷新会重试，已撤销或无效 token 视为结束。待撤销凭据不进入普通偏好、导出、聊天记录或日志，成功后从安全存储删除。安全存储写失败会保留原绑定并报告错误，以免丢失可撤销凭据。

验证：`flutter test --no-pub test/relay` 共 112 项通过，包含独立地址隔离、设置持久化、直接绑定、待确认/已确认离线解绑、进程重启撤销恢复、HTTP 挂起时本地移除、多次解绑、晚到 claim、存储失败、期限到期和 UI 删除行为。挂起的 claim、同步及 DELETE 不阻塞本地设置、扫描和解绑；结果未明的 claim 撤销保护时间保存在安全存储中，进程重启后继续生效。所有测试使用协议测试 transport，未进行实体手机验收。

正式手机构建使用 `tool/build_protected.ps1`，保留受保护素材、私有中继构建参数和现有版本发布流程。本次 stable 更新采用 `1.0.4.1 / build52`，发布序号为 55；用户操作说明见 [发布说明](../update/RELEASE_1.0.4.1_BUILD52.md)。真机安装和联动闭环待设备连接后验收。
