# PC Agent 私有服务器构建

自用构建可以内置默认联动服务器并隐藏其技术地址。默认地址只保存在本机的 `.asset_protection/relay_server.json`，整个目录已由 Git 忽略。仓库内的示例和公开文档只使用占位地址，不附带真实部署地址或已生成的配置密文与密钥。

## 配置与构建

将 `server-config.example.json` 复制到上述本机路径，填入已验证证书的 HTTPS origin。只接受 `v: 1` 和 `server_base_url` 两个字段；地址不能包含 API 路径、用户名密码、查询或片段。配置中不填设备 token、管理员 token 或二维码配对密钥。

之后继续使用现有加密构建脚本：

```powershell
powershell -ExecutionPolicy Bypass -File .\tool\build_protected.ps1 -Target apk -Mode debug
# 正式包：将 -Mode debug 改为 -Mode release
```

脚本检测本机私有配置，先扫描 Git 当前可提交的文件；如果其中包含配置的服务器主机名或 IP，构建会失败。随后用随机密钥、随机 nonce 和 AES-256-GCM 加密配置，将密文和密钥通过忽略的 `relay_server.defines.json` 注入本次构建，不生成含真实地址的 Dart 源码。Release 同时沿用 Dart 混淆。`run_protected.ps1` 也采用相同配置。

可用 `-RelayServerConfig` 指定另一份本机配置文件。该文件必须自行保存在 Git 忽略位置；如果误放在可提交文件中，地址扫描会拒绝构建。不提供私有配置的公开 checkout 仍使用原有扫码服务器信任流程。

## 内置默认与自选中继

内置默认在联动管理页显示“默认已配置”等通用提示，不显示其实际地址。用户可在「PC Agent 联动 → 云中继设置」填写自己的 HTTPS origin；留空恢复内置默认。自选地址必须满足上述 HTTPS origin 校验。相机扫码、手机命名、配对授权、解绑和重新配对继续按共享协议操作。

中继设置只影响之后的新配对。扫码时比对二维码服务器和当前选择的中继，不匹配时拒绝申请，需用户先修改设置并重新扫码；没有内置或自选地址的公开构建保留扫码后显式信任服务器的流程。

修改默认中继不会改写已有绑定或转发其凭据。每份旧绑定继续使用安全存储中自己的原始 origin 和独立 token 进行 HTTPS、WSS 及推送注册。解绑先原子移除本机绑定和缓存，同时安全保存最小待撤销记录；后台仅用该记录的原始 origin 和 token 重试自身 DELETE，不向新中继发送，也不阻塞重新配对。安全存储写失败时保留原绑定并报告错误。

配置密文缺字段、损坏或密钥不匹配时停止连接，不回退到其他地址，也不关闭 TLS 校验。联动凭证继续从角色存档与聊天备份中排除。

加密用于减少源码和 APK 中的明文地址暴露。应用运行时必须解密并连接服务器，分析运行进程或网络连接仍可得到目的地址；它不能保证服务器地址对 APK 使用者完全保密。

## 提交前

不要提交 `.asset_protection`、私有配置、生成的 build definitions、APK 或调试符号。公开文档中的 `RELAY_HOST` / `relay.example.invalid` 都是不可用于联调的占位值。构建检查针对当前文件；已公开的 Git 历史需单独检查，不能靠当前文件替换消除历史内容。
