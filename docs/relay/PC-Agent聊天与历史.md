# PC Agent 聊天与桌面历史

虚拟手机中的 PC Agent 图标和设置中的联动入口现在打开聊天页。顶部状态栏继续由虚拟手机显示；聊天页的左上按钮打开历史侧栏，右上按钮开始新对话，底部输入框用于向所选 PC 发送真实任务。

## 首次启用

1. 在历史侧栏底部进入“配对与联动管理”，沿用原有扫码绑定流程。已配对手机无需重复扫码。
2. 在 PC 的手机联动设置中自行选择允许访问的工作区，并为对应手机开启独立的“读取历史”权限。默认关闭，原有任务操作权限不等于历史读取权限。
3. PC 与中继安装支持 `session_history v1` 的版本后，手机自动读取已授权会话列表。点击会话可获取完整的用户消息和 Agent 可见回答。

左上历史侧栏按最近 7 天、30 天和更早分组，并支持搜索会话标题。侧栏和顶部均可切换目标 PC，每台绑定拥有独立安全缓存；其他 PC 的历史不会混入当前会话。

## 发送与新建

点击右上“新开对话”，选择 PC 授权的工作区，输入任务并确认发送。手机继续使用共享协议的 `task.start`。收到 PC 接受回执中的真实 `session_id` 后，才进入新建会话；不会提前生成一个假的桌面会话。

在已有会话中发送可继续该会话。发送中、等待 PC、接受、拒绝、过期、冲突和结果未知分别显示。遇到“发送结果未明”，使用该条操作旁的“幂等重试”，保留原 `action_id` 和正文。结果未确认的新建操作会阻止重复创建；HTTP 202 和送达回执都不代表 Agent 已完成。

问题与审批可从会话内处理，审批需要明确选择。任务取消、绑定和推送设置仍在联动管理中。角色聊天与语音不会自动调用远程任务。

## 历史同步

客户端先调用 `GET /v1/features` 发现支持情况与读取权限，再按正式协议读取 `/v1/sessions` 和 `/v1/sessions/{session_id}/messages`。长消息的所有分页和分片必须来自同一 `history_revision`，收齐后拼接成一条消息并原子替换旧缓存；编辑、删除以及临时流式消息结算均通过完整新版本更新。

收到无正文的 `session.history.updated` 后，选中会话重新读取。前台另每 15 秒校准一次，未变的完整版本只检查第一页，避免反复传输整段历史。后台停止历史轮询，恢复前台同步。历史 API 的 `snapshot_seq` 不推进事件 ACK；原有连续事件游标仍由安全落盘的事件同步维护。

PC 离线时可显示已同步的完整历史；网络断开时保留本地安全缓存，并显示离线提示。正在同步的新版本不会拼接进旧版本。尚未同步、旧版本不支持及未授权分别显示说明，不用任务摘要伪装聊天正文。撤销读取权限、移除授权会话或解绑后，相应历史缓存立即清理。缓存与凭证使用独立安全存储，不进入角色存档或聊天导出。

## 当前验证边界

手机端使用测试 transport 验证协议、分片、版本变化、撤权、断线缓存、正文展示、任务幂等和新会话真实映射。测试数据不会被生产 APK 导入。正式在线验收需 PC、中继扩展部署完成，并由用户在 PC 选择工作区和开启此手机的历史读取权限。

当前后台推送渠道仍未配置；前台同步和恢复后的补拉可用，不能据此承诺锁屏或系统回收后的即时远程提醒。

构建沿用 `tool/build_protected.ps1`，测试安装目标为 `a43d2d7a`。正式契约副本见 [relay-v1-contract.md](relay-v1-contract.md)，配对及推送配置见 [PC-Agent联动使用说明.md](PC-Agent联动使用说明.md)。
