# 动作选择器：小上下文与自然演出

本轮修改以 `D:/Ryza_chat/ryza_chat_mvp` 当前源文件为准，未重新生成动作 JSON，未构建或安装 APK。

## 选择流程

1. 本地按当前骨骼、服装、基础姿态及坐姿过滤资源。生成组合的动作含义由实际动画层对应的已知动作组提供；必须在同一阶段同时存在左右层，才能标注双手动作。有任何额外未标注层的组合不进入自动规划候选，完整配方仍可在手动组合页使用。
2. 本地检索首轮最多 16 个动作组/配方，加上可用的高层动作和 `none`。按中文/日文双字词、英文词与目录词频排序，降低皮肤编号、轨道和生成模板文字的干扰；提供常见中日英动作检索别名。最近动作降权，在相近候选中保留不同部位的组合。
3. LLM 只看到当前用户输入、本轮非译文片段、最近最多 4 个动作、当前姿态与手动锁定状态、当前表情/强度、已结算情绪与状态和上一语音情绪。历史正文和本轮正文不再在 `shared_context` 重复发送。原段落编号以 `[id:N]` 保留，删除译文不改变规划结果的索引。
4. 需要更准确的资源时，模型可请求一次补充检索，并给出 `search_query`。补充窗口替换首轮窗口，最多 48 个动作组/配方。`catalogue_complete` 仍如实表示是否覆盖完整可用目录，`can_expand` 独立表示是否还有补充检索机会。
5. 扩展仍无匹配则保持现有动作；不能用转肩等近似动作冒充精确要求。保持原有表情、语音和动作独立规划、按台词播放与播放前资源校验。

## 上下文预算与连续性

- 用户输入最多 800 字符；本轮非译文正文合计约 2,200 字符，另加段落编号和说话人标记，每个片段最多 520 字符。
- 候选描述最多 220 字符；状态变化原因最多 120 字符。字符预算不等于实际模型 token 数。
- 当前证据被裁剪时标记 `evidence_truncated`，本地也会禁止根据残缺输入启动动作或改变姿态。候选描述摘要不完整时列入 `incomplete_candidates`，不执行该候选。表情、状态结算及语音仍保留自己的完整规划输入。
- `none` 表示本段不发起新主要动作；现有眨眼、成套表情、资源授权的身体轻晃和细微腿部待机继续承担自然演出。无需为了“生动”让每句话都换大动作。
- 已结算情绪、当前表情和上一语音情绪保留在动作上下文，减少上下轮状态割裂。剧情明确转折仍以本轮台词和旁白为依据。

## 开销控制

- 大配方 JSON 解析和动作语义关联通过 `compute` 在后台 isolate 执行。
- 大目录的首次分词和词频索引通过 `Isolate.run` 构建，避免在 UI isolate 执行冷检索；后续检索与补充请求复用索引。
- 按外观、资源代次、基础姿态、手动姿态、当前表情和强度复用能力快照，相关状态变化时重新生成。
- 检索维护有限 top-k，而不是每轮排序整个目录。缓存只保留最近能力目录。
