# NPC 联系人及 PC Fish Audio 连接修复

## NPC 交换联系方式

主聊天支持在发言或上下旁白输入中提出交换联系方式、添加好友或微信、QQ、LINE 等请求。对应 NPC 必须在本轮自己的台词里同意，之后点击「加入信息」才建立联系人。

修复了中文、日文、英文姓名格式与部分自然日语同意台词漏识别的问题。联系人确认在完整回复提交后显示，不再依赖 TTS 或动作规划成功。信息页立即显示该联系人，聊天入口与联系人一起保存在当前存档；切换新存档不会沿用旧档联系人。

拒绝、犹豫、旁白代替本人同意、翻译和隐藏模型文本不能建立联系人。此修复不会扫描历史对话并自动补加联系人；之前未出现确认的交换，可在当前对话中再次提出。

## Windows Fish Audio 自动代理

Fish Audio 首次连接某个服务地址时，先用无认证、无台词的 HEAD 请求探测直连。直连不可达时依次探测进程环境中的 HTTP 代理与 Windows 当前用户的系统 HTTP 代理，选择可用路径后才发送语音合成请求。无需开启 TUN，代理软件仍需运行并启用系统代理，或给应用启动进程配置 HTTP 代理环境变量。

HTTP 401、404、405 等响应说明网络链路已建立，不会把它们当成探测失败。探测不发送 API Key、音色 ID 或用户正文；HTTPS 合成请求通过 HTTP CONNECT 代理，继续验证服务器证书。

按服务地址缓存路由两分钟，同一地址的并发语音请求共享探测。可重试的网络异常或合成期限到达后，现有请求重试会重新选路；传输层不会额外重放合成 POST。证书错误保持拒绝，不把它当成可以忽略的网络错误。系统代理配置变化最长可能受两分钟缓存影响。本地回环 TTS 地址直接连接，并遵循代理例外列表。

支持 `http_proxy`、`https_proxy`、`all_proxy` 及其大写形式，值需为 HTTP CONNECT 代理地址；也读取 Windows 静态系统代理和例外列表。不解析 PAC/WPAD，不支持 SOCKS、需要代理账号密码的地址或 TLS 到代理服务器的 `https://` 代理。使用此类配置时，请让代理软件提供并启用 HTTP 混合端口。不会关闭 TLS 验证。

改动仅作用于 Windows Fish Audio 的默认传输，聊天 LLM 与其他 TTS 保留各自客户端。

## 验证范围

73 项相关测试通过，Flutter 全项目静态检查无问题。联系人回归实际经过主聊天发言／旁白请求、日语姓名同意、点击确认、TTS 缺配置／HTTP 401 失败及虚拟手机联系人窗口；另覆盖即时刷新、发送、重启及存档隔离。代理回归覆盖解析、直连优先、不可达切换、并发探测、缓存过期、取消与超时、本地回环代理转发。Windows 网络通道单独 C++ 编译检查通过。

本机无认证网络探测确认 Fish Audio 直连超时、经已有系统 HTTP 代理能建立 TLS/HTTP 连接。此探测未生成语音，不代表真实在线 TTS 端到端验收。修复已通过受保护脚本重新构建 Android 和 Windows release，两端保留 `1.0.4+38`；本次发布覆盖 GitHub `v1.0.4` 正式版的 APK 与 Windows ZIP。未进行设备安装或真实在线语音生成。
