# 动作规划 action:none 格式故障修复

## 问题与原因

截图中的用户请求是拍手，主角也已答应，但日志出现 `FormatException: Incomplete planner segments`，整轮动作随后回退为 `none`。

原动作解析要求模型返回的段落数量与目标台词数量完全一致。多返回旁白、译文或漏一条台词，都会让同一轮有效动作一起丢失。提示词输出示例固定使用 `id:0`，而“旁白0、主角1、译文2”的真实目标编号通常为1，容易引发编号错误。

拍手本身存在真实资源 `grp_fg_024`。用截图中的日语、旁白和当前原始配方目录作检索探针，它位于首轮16个候选中的首位；该探针未模拟当前服装与姿态的运行时过滤，因此不能替代实际模型与角色播放验收。

## 修改行为

- 根据本轮真实台词ID生成JSON示例，并提供仅含目标主角台词的 `dialogue_lines`；正文仍有字符预算，不发送整个动作目录。
- 动作逐段验证。额外旁白、译文和坏条目不再丢弃其他合法动作。数字字符串ID可归一；只有唯一目标、唯一返回条目且完全缺少ID字段时才能归到该目标。显式错误ID、`null`、重复ID或多条无ID不会按位置猜配。
- 无效JSON、漏行和非法行最多修复一次，只重试相关ID。格式修复与候选扩展共用最多两次LLM请求；第二次始终关闭进一步扩展选项。明确的目录请求可以重选原先的 `none` 段落。
- 首轮合法结果先按当轮候选白名单验证，扩展窗口替换后仍保留。第二次网络失败或超时不会丢弃首轮有效动作；无法修复的段落独立回退为 `none`。
- 保留能力校验、描述不完整过滤、截断证据保护、否定/引用/过去事件提示、手动姿态锁定和姿态切换后的动作抑制。不会为了减少 `none` 随机猜动作。
- 动作请求总预算28秒，单次最多20秒，为外层30秒超时保留余量。日志采用原有限频接口，分别计数选中动作、无需新动作、无效/缺失段落、能力不匹配、证据截断、描述不完整及姿态切换保持。

`none` 的正常含义仍是本段不启动新的主要动作，不能将所有 `none` 都视为故障。实际播放还需通过外观、资源代次和姿态检查；“选中动作”不等于已经播放。
